# MOTUS Claude Autopilot — 운영 계획서

2026-10-30 사용자 지시: "루인 작업이 없어도 주도적으로 작업 방향을 잡고 이 프로젝트를 완성시켜. 1시간 단위로 모니터링·감시하며 작업을 계속해."

이 문서는 Claude의 1시간 루프가 매 실행마다 읽는 기준이다. 진행 상태는 맨 아래 **작업 기록**에 남긴다.

## 1. 완성의 정의

아래 다섯 가지가 모두 충족되면 MOTUS Daily는 완성으로 본다.

1. **무개입 정시 발행.** 연속 10 영업일 동안 세 카테고리가 사람의 수동 실행 없이 발행되거나, 정당한 사유(휴장, 검증된 이벤트 부족)로 SKIP된다.
   - 국내증시: 06:17 KST 전일판, 08:25 재시도
   - 미국증시: 06:45 KST
   - AI: 12:30 KST
   - 허용 지연은 목표 시각 + 3시간이다.
2. **품질 정책 위반 0건.** 제목은 날짜·영문 지수명·상품명·조사 오류·반복 제목이 없어야 한다. 본문은 raw URL·내부 라벨·영문 복붙·boilerplate가 없어야 한다.
3. **데이터 신뢰성.** 단일 비공식 소스 장애(Yahoo 429 등)만으로 하루가 통째로 HOLD되지 않는다. 독립 소스 교차검증은 유지하고, stale·proxy·fixture fallback은 금지한다.
4. **운영 가시성.** 운영자가 하루 상태(발행·SKIP·HOLD와 사유)를 파일 하나로 볼 수 있다.
5. **기록 무결성.** `ops-data` ledger, Library, Weekly feed, Search 등록이 발행과 1:1로 맞는다.

## 2. 매시간 루프 절차

> 2026-10-30 08:58 KST 사용자 지시로 변경: 모니터링은 블로그 에이전트(기사 품질 담당 Claude 세션, Issue #43)가 맡는다. 이 문서의 1시간 루프는 중단했다. 이 세션은 에이전트의 작업과 GitHub 지시(Issue #43, 에이전트 PR 댓글)에 맞춰 작업 방향을 잡는다. 에이전트가 리뷰 대기로 멈춘 PR을 독립 리뷰하고, 에이전트가 넘긴 결함을 고친다. 아래 절차는 에이전트가 모니터링에 참고하는 기준으로 남긴다.

1. **동기화.** `git fetch`, `origin/main`과 `origin/ops-data`를 확인한다. GitHub는 REST(`gh api`)만 쓴다.
2. **감시(오늘 KST 기준).**
   - 카테고리별 ledger와 `auto-publish.json`, 최근 Actions 실행 결과를 본다.
   - 결제 차단, 인증 만료, 빌드 실패, 새 HOLD 사유를 찾는다.
   - 다른 작업자(Codex·루인)의 새 commit이나 PR이 있으면 먼저 독립 검토한다.
3. **누락 실행 복구.** GitHub 예약 실행은 보통 2~3시간 늦게 시작한다(B2 측정). 그래서 카테고리별 **유효 재시도 시각**이 지나고 45분이 넘도록 그 이후 시작된 실행이 없으면 `MOTUS Daily Production Gate`를 `workflow_dispatch`로 1회 실행한다(`category`, `execute_publish=true`).
   - 유효 재시도 시각: 국내증시 08:25(KRX 공식 T-1 데이터가 08:00에 갱신됨), 미국증시 08:40(증권사 아침 시황 필요), AI 12:30. 그보다 이른 실행은 설계상 HOLD되므로 하지 않는다.
   - 해당 identity가 ledger에 PUBLISHED나 SKIP으로 있거나, 실행이 진행·대기 중이면 하지 않는다.
   - 카테고리당 하루 2회까지만 한다(08시대 1회, 10시대 재시도 이후 1회).
   - gate와 중복 방지는 workflow 안에서 그대로 적용된다.
4. **장애 수정.** 새 HOLD·FAILED의 근본 원인이 코드에 있으면 브랜치에서 고치고 회귀 테스트를 추가한다. 테스트는 `TZ=UTC`와 `TZ=Asia/Seoul` 양쪽에서 돌리고 PR을 올린다.
5. **백로그 진행.** 장애가 없으면 아래 백로그에서 다음 항목 1개를 진행한다.
6. **기록.** 코드나 운영에 변화가 있었던 실행만 이 문서의 작업 기록에 한 줄을 남긴다. 그 줄은 해당 PR에 함께 넣고, 감시만 한 실행은 기록하지 않는다. 사용자에게는 발행 실패, 새 장애, 사용자 결정이 필요할 때만 짧게 알린다.
